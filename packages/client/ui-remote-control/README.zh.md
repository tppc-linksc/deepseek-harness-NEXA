# @deepseek-ai/dsh-client-ui-remote-control

[English](README.md) | 中文

`@deepseek-ai/dsh-qrcode-remote` 的浏览器端连接界面。它向 `sidebar.footer.trailing` 注入一个 36 像素的“**连接移动端**”图标，与“设置”处于同一页脚行并紧邻其右侧；用户打开后会自动创建一个短时微信小程序码，并在紧凑浮层中展示。常规界面只保留“是否允许手机连接这台电脑”一个开关，不显示 Relay 地址、电脑 ID、指纹、配对设备管理、协议状态或手动确认。

电脑是唯一执行权威。小程序只镜像电脑拥有的工作区、会话、消息、工具输出、状态和审批请求；手机输入被送入选中的电脑会话。双向签名配对仍保留在 Host 协议中，但用户打开电脑端浮层的动作只授权当前精确匹配的新 challenge，因此微信扫码成功后会直接进入镜像会话，不需要再次确认或点击“进入会话”。旧 payload 回退码不会作为用户可扫描的产品二维码展示。

Host 连接状态以完成身份认证的传输状态为准，而不是只判断是否存在 socket 对象。Relay 断开后会按有上限的指数退避自动重连；打开浮层会重启已经失效的 Host；成功刷新状态会清除短时网络错误。桌面快照会包含每个未归档会话，包括刚创建的空白会话，因此小程序抽屉是电脑状态的忠实投影，而不是另行过滤的任务列表。

## 模型体验

无。浏览器控件不注册 prompt、schema 或模型上下文；经过独立准入的手机输入由 Host 服务处理。

#### KV Cache 影响

无；本包不组装也不发送任何模型供应商请求。

## 已知限制与延期工作

- 浮层能展示连接可用性，但不能代替 DNS、TLS、Redis、微信服务端密钥或公网 Relay 的部署。
- 二维码配对、小程序挂起后的重连和 SOTER 审批仍需在发布版真机上验证。
