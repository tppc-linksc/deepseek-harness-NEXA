# Agent Note: 将 NEXA Remote 定义为应用级控制端

Status: implemented

[English](2026-08-24-nexa-remote-application-control.md) | 中文

## 问题

无感薄客户端流程让远程查看和向已有会话输入变得可用，但阻止了电脑不在身边时的常见工作：在已有工作区启动会话、注册电脑上的另一个项目、创建项目目录，以及修改安全设置。因为手机不执行就禁止这些请求，混淆了执行权归属与控制权。开放任意桌面文件系统访问或建立第二套手机运行时虽然能填补交互缺口，却会削弱电脑的权威和安全边界。

## 决策

NEXA Remote 是一台已配对 DeepSeek Harness 电脑的应用级控制端。小程序采用移动端适配的导航和呈现，同时保留桌面功能语义。它查看电脑状态并提交经过版本化、身份认证且幂等的控制请求；电脑负责校验、执行、持久化并发布所有权威结果。[薄客户端决策](2026-08-22-nexa-remote-thin-client.md)中的微信无感扫码和后台配对流程继续作为唯一常规连接路径。

## 执行权威

手机永远不运行 Agent、不调用模型、不执行工具、不保存权威会话或工作区，也不直接修改项目文件。已配对电脑离线时，手机不能继续执行。Relay 只转发不透明加密帧，不能把手机请求自行转换为 DSH 操作。Host 只根据适配器真实存在的方法发布能力，并拒绝未声明动作。

## 远程操作

控制面覆盖新建会话、提交指令、取消正在执行的任务、审批决定、安全注册或创建工作区，以及结构化设置。会话与工作区修改成功后重新读取电脑快照，不在手机插入乐观记录。审批允许继续由既有 DSH 审批服务产生一次性授权。普通用户问题回答在具备等价类型化 DSH 路由前保持缺席，因此不会被声明为能力。

## 工作区与设置安全

工作区浏览从电脑配置的授权根开始，只返回短时不透明目录引用，不返回绝对路径。Host 为每次请求重新校验规范路径包含关系、设备身份、符号链接、敏感目录和名称。P0 允许列目录、注册已有目录或创建一层目录，不提供移动、重命名、删除、上传和任意文件读写。设置由 Host 持有描述符和风险标签；P0 允许修改电脑名称，敏感设置仅限本地，并用摘要和 CAS 修订号拒绝过期或被篡改的写入。

## 考虑过的替代方案

**除发送与停止外保持小程序只读。** 这种方案保持最小控制面，但只要目标项目或会话尚不存在，就无法完成电脑不在身边时的主要工作流。

**传输桌面画面和输入。** 屏幕遥控可以保留每个像素，但手机交互很差，会暴露无关桌面内容，并绕过 DSH 的类型化准入和审批边界。

**在手机或 Relay 运行第二套 Agent 运行时。** 第二套运行时允许手机离线执行，但会为凭据、文件、会话和工具建立另一个权威，也违背任务留在已配对电脑上的部署承诺。

## 后果

用户获得与桌面一致的控制语义，而不需要桌面尺寸的交互界面或第二套执行环境。能力协商、幂等、不透明目录引用和设置修订号增加了协议与适配器复杂度，并且每次操作都要求电脑可达。文件系统与设置允许列表是刻意限制；其他桌面操作在新的安全决策扩展前仍只允许本地执行。
